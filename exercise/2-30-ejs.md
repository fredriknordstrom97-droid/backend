## Background: static files and templates

A web server sends two kinds of content:

- **Static files** are sent as they are: CSS, images, JavaScript for the browser. Express has a middleware for this,
  `express.static()`: give it a directory, and a request for `/css/style.css` gets the file `css/style.css` in that
  directory. The convention is a directory `public/`.
- **Dynamic pages** are built for each request. A *template* is an HTML file with holes in it; the route gives the
  template its data, and the *template engine* fills in the holes and returns HTML. In Express that is
  `res.render('index', { title: 'Home' })`.

EJS ("Embedded JavaScript") is a template engine where the holes are written with tags:

| Tag | Does |
|---|---|
| `<%= value %>` | prints the value, **escaped**: `<` becomes `&lt;`, so it shows as text and is never read as HTML |
| `<%- value %>` | prints the value **as it is**, unescaped, as HTML |
| `<% code %>` | runs JavaScript and prints nothing, for an `if` or a loop |

## 2. Serve a static file

Create `public/css/style.css` with some style for the pages to come:

```css
body {
  max-width: 40rem;
  margin: 0 auto;
  padding: 1rem;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
}

nav a {
  margin-right: 1rem;
}

footer {
  margin-top: 2rem;
  border-top: 1px solid #ccc;
  color: #666;
}
```

Then let Express serve the directory `public/`. Add this to `src/app.js`, the import at the top and the `app.use()`
before the routes:

```js
import path from 'node:path'
```

```js
app.use(express.static(path.join(import.meta.dirname, '..', 'public')))
```

`import.meta.dirname` is the directory of the file the code is in, here `src/`. From there `'..', 'public'` is the
directory `public/` in the root of your repo. A path built this way works whatever directory you start the server
from.

```bash
curl -i http://localhost:$PORT/css/style.css
```

You get `200 OK`, `Content-Type: text/css; charset=utf-8` and the file. Note that the URL has no `public`: the
directory is the root of what `express.static()` serves.

## 3. Install EJS and render a page

Stop the server with `Ctrl+C` and install EJS:

```bash
npm install ejs
```

Tell Express to use EJS and where the templates are. Add this to `src/app.js`, after `const app = express()`:

```js
app.set('view engine', 'ejs')
app.set('views', path.join(import.meta.dirname, 'views'))
```

You never import `ejs` yourself: Express loads it when you render the first page.

Create the home page as `src/views/index.ejs`:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title><%= title %> | My backend</title>
  <link rel="stylesheet" href="/css/style.css">
</head>
<body>
<h1>Hello World</h1>

<p>This page is made with Express and the template engine EJS.</p>
</body>
</html>
```

The pages get a router of their own, as the API did in 2-20. Create `src/route/page.js`:

```js
import express from 'express'

const router = express.Router()

router.get('/', (req, res) => {
  res.render('index', { title: 'Home' })
})

export default router
```

`res.render('index', ...)` finds `index.ejs` in the views directory, fills in `title` and sends the HTML.

Remove the route for `/` from `src/app.js`, import the router and mount it on `/`. Start the server with
`npm run dev` and open http://localhost:3000/ in the browser: a page with a heading, in the font from the CSS file.

<details>
<summary>The whole <code>src/app.js</code></summary>

```js
import path from 'node:path'
import express from 'express'
import pageRouter from './route/page.js'
import apiRouter from './route/api.js'
import healthRouter from './route/health.js'

const app = express()

// Print each request, then let it go on to the routes
app.use((req, res, next) => {
  console.log(req.method, req.url)
  next()
})

app.set('view engine', 'ejs')
app.set('views', path.join(import.meta.dirname, 'views'))

app.use(express.static(path.join(import.meta.dirname, '..', 'public')))

app.use('/', pageRouter)
app.use('/api', apiRouter)
app.use('/api/health', healthRouter)

export default app
```

</details>

Run `npm test -- src`. The test `GET / says Hello World` from 2-10 fails: it expects the text `Hello World\n`, and the
answer is now a whole page. The test was right about the old app; now the app has changed on purpose, so change the
test. Replace it in `src/app.test.js` with:

```js
test('GET / is a web page that says Hello World', async () => {
  const res = await fetch(`${baseUrl}/`)
  assert.equal(res.status, 200)
  assert.match(res.headers.get('content-type'), /text\/html/)
  assert.match(await res.text(), /<h1>Hello World<\/h1>/)
})
```

`assert.match()` checks a string against a regular expression, so the test needs only the part of the page that
matters. The `/` in `</h1>` is written `\/`, since `/` ends the regular expression.

## 4. A header and a footer for all pages

Every page needs the same start, with `<head>` and a menu, and the same end. Instead of copying them into each
template, put them in templates of their own, *partials*, and include them.

Create `src/views/partials/header.ejs`:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title><%= title %> | My backend</title>
  <link rel="stylesheet" href="/css/style.css">
</head>
<body>
<header>
  <nav>
    <a href="/">Home</a>
    <a href="/hello?name=Ada">Hello</a>
    <a href="/api/health">Health</a>
  </nav>
</header>
<main>
```

and `src/views/partials/footer.ejs`:

```html
</main>
<footer>
  <p>DA559A Introduction to Back-End Development</p>
</footer>
</body>
</html>
```

Then `src/views/index.ejs` is only what is special for the page:

```html
<%- include('partials/header', { title }) %>

<h1>Hello World</h1>

<p>This page is made with Express and the template engine EJS.</p>

<%- include('partials/footer') %>
```

`include()` renders the partial and returns its HTML. It is printed with `<%-`, unescaped, since it is HTML from your
own template; with `<%=` you would see the tags as text on the page. `{ title }` passes the page's title on to the
header.

Reload the page: the same heading, now with a menu and a footer. Run the tests again; they still pass.

## 5. A page with data from the request

Add a page `GET /hello` that greets the name in the query string, and `World` when there is none. The link `Hello` in
the menu goes to `/hello?name=Ada`, which should show the heading `Hello Ada`.

Create `src/views/hello.ejs` with the header and the footer, and this in between:

```html
<h1>Hello <%= name %></h1>

<p>Change the name in the query string: <code>/hello?name=Bob</code>.</p>
```

Then write the route in `src/route/page.js`.

Hint: as in 2-20, the name is in `req.query.name`, and `??` gives a default. Give both `title` and `name` to
`res.render()`.

<details>
<summary>A solution</summary>

```js
router.get('/hello', (req, res) => {
  const name = req.query.name ?? 'World'
  res.render('hello', { title: 'Hello', name })
})
```

`{ title: 'Hello', name }` is short for `{ title: 'Hello', name: name }`.

</details>

Add a test last in `src/app.test.js`:

```js
test('GET /hello?name=Ada greets Ada on a web page', async () => {
  // 1. Fetch /hello?name=Ada and check that the status is 200
  // 2. Check that the page has the heading <h1>Hello Ada</h1>
})
```

<details>
<summary>A solution</summary>

```js
test('GET /hello?name=Ada greets Ada on a web page', async () => {
  const res = await fetch(`${baseUrl}/hello?name=Ada`)
  assert.equal(res.status, 200)
  assert.match(await res.text(), /<h1>Hello Ada<\/h1>/)
})
```

</details>

## 6. XSS: why `<%=` escapes

The name on the page comes from the URL, and anyone can write anything in a URL. Open this in the browser:

```text
http://localhost:3000/hello?name=<b>Ada</b>
```

The heading shows `Hello <b>Ada</b>`, tags and all, and not a bold Ada. Look at the source of the page (`Ctrl+U`):
`<%=` has written `&lt;b&gt;Ada&lt;/b&gt;`, which the browser shows as text.

Now change `<%= name %>` to `<%- name %>` in `hello.ejs`, and reload. Ada is bold: the browser reads the name as HTML.
Then try a name that is a script:

```text
http://localhost:3000/hello?name=<script>alert('XSS')</script>
```

The browser runs it and shows a dialog. That is **XSS, cross-site scripting**: the page runs JavaScript that someone
else wrote. Here it only shows a dialog, but the same script could read what is on the page, send the user's data
somewhere else or act as the user. An attacker only needs to get a victim to open a link like the one above.

Change it back to `<%= name %>` and reload: the script is shown as text again. The rule: print data with `<%=`, always.
Use `<%-` only for HTML you wrote yourself, like the partials.

Add a test that guards the escaping, so a change to `<%-` breaks a test and not your users:

```js
test('the name is escaped, so a script is not run', async () => {
  const name = encodeURIComponent('<script>alert(1)</script>')
  const res = await fetch(`${baseUrl}/hello?name=${name}`)
  const html = await res.text()
  assert.match(html, /&lt;script&gt;/)
  assert.doesNotMatch(html, /<script>/)
})
```

`encodeURIComponent()` writes the name the way it must look in a URL, which the browser did for you above. Change to
`<%-` once more and run `npm test -- src` to see the test fail; then change it back.

Last, a test that the CSS file from step 2 is served:

```js
test('the CSS file is served from public/', async () => {
  // 1. Fetch /css/style.css and check that the status is 200
  // 2. Check that the Content-Type is CSS (text/css)
})
```

<details>
<summary>A solution</summary>

```js
test('the CSS file is served from public/', async () => {
  const res = await fetch(`${baseUrl}/css/style.css`)
  assert.equal(res.status, 200)
  assert.match(res.headers.get('content-type'), /text\/css/)
})
```

</details>

The partial is included with `<%=`, which escapes its HTML. Use `<%- include(...) %>`.

<summary>The browser does not show the dialog in step 6</summary>

script is there.
